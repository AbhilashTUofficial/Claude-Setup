## Official `skills/shadcn` (maintainer-authored, in repo) [V read in full: SKILL.md, rules/base-vs-radix, composition, forms, icons, styling]
Authority: same repo/maintainers → treated as official guidance, ranked just under source code. Not all of it matches the CLI (see conflicts).
- Context injection: `npx shadcn@latest info --json` (fields used: aliases, isRSC, tailwindVersion, tailwindCssFile, style, base, iconLibrary, resolvedPaths, framework, packageManager, preset, installed components).
- Critical rules (verbatim intent): `className` for layout not colors/typography; no `space-x/y-*` → `flex gap-*`; `size-*` when w=h; `truncate`; no manual `dark:` colors → semantic tokens; `cn()` for conditionals; no manual z-index on overlays. Forms: `FieldGroup`+`Field`; `InputGroup` uses `InputGroupInput/Textarea`; icon-buttons in inputs via `InputGroupAddon`; 2–7 option sets → `ToggleGroup`; `FieldSet`+`FieldLegend` for related checkboxes/radios; invalid = `data-invalid` on Field + `aria-invalid` on control, disabled = `data-disabled` + `disabled`. Structure: items inside Group (`SelectGroup`, `DropdownMenuGroup`, `CommandGroup`…); Dialog/Sheet/Drawer always need Title (`sr-only` ok); full Card composition; Button has no isPending → `Spinner data-icon="inline-start"` + `disabled`; `TabsTrigger` inside `TabsList`; Avatar needs `AvatarFallback`; use Alert/Empty/Separator/Skeleton/Badge instead of custom markup. Icons: `data-icon="inline-start|inline-end"`, no sizing classes on icons inside shadcn components, pass icon components not string keys; always import from project's `iconLibrary`.
- Base vs Radix API table (rules/base-vs-radix.md): triggers `asChild` (radix) vs `render={<Button/>}` (base) [+ `nativeButton={false}` when render target isn't a button]; Select: base needs `items` prop and `{value:null}` placeholder item, `alignItemWithTrigger` vs radix `position="popper"`, base supports `multiple` + object values (`itemToStringValue`); ToggleGroup: radix `type="single|multiple"` w/ string defaultValue vs base `multiple` boolean + array defaultValue; Slider: base scalar value for one thumb, radix always array; Accordion: radix `type` + `collapsible` + string defaultValue vs base no `type`, `multiple`, array defaultValue. Toast: Base UI `toast` component (`toast.add({title})`) vs `sonner` for Radix/Aria.
- Workflow rules: check installed first; `search` before writing custom UI; `docs <component>` before using a component; review added files and fix imports for third-party registry items (non-UI files may hardcode `@/components/ui/...`); registry must be explicit (never default a registry for the user); preset switching = overwrite (`apply <code>`) | partial (`apply <code> --only theme,font`; `icon` intentionally unsupported) | merge (`init --preset <code> --force --no-reinstall` + per-component `--dry-run`/`--diff`) | skip; `--overwrite` only with explicit approval; never fetch raw GitHub files — use CLI.
- Other files: `cli.md`, `customization.md`, `registry.md`, `mcp.md`, `design-system.md` (DESIGN.md → themed app), `design-system-page.md`, `rules/chat.md` (MessageScroller/Message/Bubble/Attachment/Marker/Trace), `evals/evals.json`, `migrate-radix-to-base/*` (a second skill: converting Radix components to Base UI; class-mapping, consumer-props, wrapper-shapes, per-category guides).
- Conflicts with CLI behavior [V]: skill/docs/`-d` help use `--preset base-nova` which the CLI rejects; skill's "Named presets: nova vega maia lyra mira luma" omits sera, rhea (both exist); skill says `base` is `radix` or `base` (aria exists too); `--defaults` described as `--preset=nova` (cli.mdx) vs `base-nova` (help string) — code uses nova URL with resolved base default "base".
