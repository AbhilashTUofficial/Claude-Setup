## CLI architecture [V]
- Entry `packages/shadcn/src/index.ts` (commander). Commands in `src/commands/*.ts`: add, apply, build, diff (deprecated), docs, eject, info, init, mcp, migrate, preset, search, view, registry/{add,build,mcp,validate}. Heavy logic lives in `packages/registry/src/*` imported as `@shadcn/registry/internal/*`: `add-components.ts` (orchestrator), `registry/{resolver,api,fetcher,loader,namespaces,address,github*}.ts`, `updaters/*` (update-files, update-css-vars, update-css, update-dependencies, update-env-vars, update-fonts, update-tailwind-config[v3]), `transformers/*`, `codemod/*` (Babel-based text-edit engine that replaced ts-morph — comments in transformers refer to "ts-morph runner" parity).
- `init` order: parse opts → validate template/preset name → monorepo-root check → existing components.json prompt (overwrite? re-install?) → [no `-p` & no components & no `-d`: prompt template (new project, no package.json), monorepo (if template supports), BASE (`promptForBase`), then interactive preset list] → build init URL (`ui.shadcn.com/init?…` or from preset code/name/URL) → `resolveRegistryBaseConfig` fetches the `registry:base` item (cache) → `runInit` (writes components.json from item.config, installs deps, fonts, files, css vars). `options.base ?? presetBase ?? existing config base ?? "base"` (registry-base default) [V init.ts L478-500]. Base-switch on reinit prompts (`confirmBaseSwitch`). components.json is backed up to `components.json.bak`-style file and auto-restored on failure (`FILE_BACKUP_SUFFIX`, `process.on("exit")`).
- Preset arg forms accepted: URL, preset code (`^[ab][0-9A-Za-z]{1,9}$`), or one of DEFAULT_PRESETS keys (nova vega maia lyra mira luma sera rhea). **`base-nova` (used in the official skill/docs/`-d` help text) is rejected**: lab: `Invalid preset: base-nova. Available presets: nova, vega, maia, lyra, mira, luma, sera, rhea` [V lab]. Preset codes do not encode the base ("Preset codes no longer carry base"); base comes from `--base`/prompt/URL.
- Preset code algo [V preset.ts]: bit-pack fields (V1 = menuColor3, menuAccent3, radius4, font6, iconLibrary6, theme6, baseColor6, style6 = 40 bits; V2 adds chartColor6 + fontHeading5 = 51 bits) into an integer (index in each value list, first field = lowest bits), base62-encode, prefix version char (`a`=v1, `b`=v2). Rules: never reorder value arrays, append only, new field default index 0, stay under 53 bits. `encodePreset` always emits `b…`. Lab: nova default = `b2fA`; `b0` = style nova + font inter (all index 0); after `apply a2r6bw --only theme` the project resolves to `b37ZhrQ6y` (theme+chart indigo, other fields kept).
- Value lists: styles nova vega maia lyra mira luma sera rhea; baseColors neutral stone zinc gray mauve olive mist taupe; themes = base colors + amber blue cyan emerald fuchsia green indigo lime orange pink purple red rose sky teal violet yellow; icon libs lucide hugeicons tabler phosphor remixicon; fonts 26 (inter noto-sans nunito-sans figtree roboto raleway dm-sans public-sans outfit jetbrains-mono geist geist-mono lora merriweather playfair-display noto-serif roboto-slab oxanium manrope space-grotesk montserrat ibm-plex-sans source-sans-3 instrument-sans eb-garamond instrument-serif); radii default none small medium large; menuAccent subtle|bold; menuColor default|inverted|default-translucent|inverted-translucent.
- Network: `REGISTRY_URL` env overrides registry root (`https://ui.shadcn.com/r`); `SHADCN_URL` derived. Init/apply send `track=1` (server-side run recording). Fetch timeout 10 s (lab failure). `SHADCN_GITHUB_URL` / `SHADCN_TEMPLATE_DIR` env override template source.
- Templates: created by `git clone --depth 1 --filter=blob:none --sparse https://github.com/shadcn-ui/ui.git <tmp>` + `git sparse-checkout set templates/<dir>`, moved into project, `adaptWorkspaceConfig` for the detected package manager, then `<pm> install` [V create-template.ts L230-283] → **requires `git` on PATH + network + GitHub**. Repo `templates/`: next-app, next-monorepo, vite-app, vite-monorepo, start-app (TanStack Start), start-monorepo, react-router-app, react-router-monorepo, astro-app, astro-monorepo (+ `laravel` handled differently: user must `laravel new --react` first). Vite template (current): React ^19.3, Tailwind ^4 via `@tailwindcss/vite`, Vite ^8, TypeScript ~6.0.2, ESLint ^10. Next template: Next 16.4.0, React 19.3.0, next-themes; ships AGENTS.md/CLAUDE.md.
- Framework detection (`get-project-info.ts`): globs `{next,vite,astro,app}.config.*`, `gatsby-config.*`, `composer.json`, `react-router.config.*` (depth 3); Next app vs pages by `app/` dir (isRSC = app dir); Astro, Gatsby, Laravel, Remix (`@remix-run/*` dep), TanStack Start (`@tanstack/react-start`), React Router, else Vite/manual.

## Transformer chain (install-time) [V transformers/index.ts]
Default order: `transformImport` (rewrite `@/registry/...` and alias imports to project aliases), `transformRsc` (strip `"use client"` when components.json `rsc:false`), `transformCssVars` (when `cssVariables:false` inline utilities from base color), `transformTwPrefixes` (apply `tailwind.prefix`), `transformRtl` (physical→logical when `rtl:true`), `transformIcons` (`IconPlaceholder` → configured iconLibrary components/imports), `transformCleanup`; `.jsx` output (tsx:false) adds `transformJsx`. Others in dir: `transform-menu` (menuColor/menuAccent cn-menu-* classes), `transform-font`, `transform-aschild`, `transform-next` (renames `middleware` → `proxy` for Next 16), `source-text` (strips BOM from registry source).
- Known quirk kept on purpose [V transform-rsc.ts L8-11]: the `"use client"` regex has the `g` flag, so with `rsc:false` "after a match the next call fails and every other file keeps its 'use client'… until that is fixed". Impact: Vite/React Router projects (rsc false) may see leftover `"use client"` directives in alternating files — harmless to Vite but noisy. Reproduction not run in lab (lab is rsc:true). [Unconfirmed in practice → unresolved]
- Style substitution (cn-* → Tailwind) is NOT in this chain; it happens in the registry build (`styles/transform-style-map.ts`) before publish: handles cva() calls, `className` attributes and `className` object properties, `mergeProps` calls. Allow-listed runtime-kept cn-* classes: `cn-menu-target, cn-menu-translucent, cn-logical-sides, cn-rtl-flip, cn-font-heading` (resolved later by menu/rtl/font transformers). `TODO: all cn-* classes to be allowedlisted` comment. Leak found in lab: `classNames: { toast: "cn-toast" }` (sonner) not transformed.

## add / registry resolution [V + D]
- `add` flow: loadEnvFiles(cwd) → getConfig; if no components.json, makes a temp config with `style:"new-york"` and (after prompting) runs init with template inferred from framework → ensureRegistriesInConfig (auto-adds `@ns` registries? — only those already known / from directory? see unresolved) → `getRegistryItems` for first item to learn its type; for `registry:style|theme|base` shows an "existing CSS variables and components will be overwritten" confirm → warn on deprecated (`toast`, `toaster`) for Tailwind v4 → `preFlightAdd` → `addComponents`.
- Universal items (`registry:item` with files carrying targets, i.e. not framework-specific) are installed without requiring init (`isUniversalRegistryItem`) — which is how GitHub-registry "any files" items work in non-React repos. [V add.ts L138; Dv]
- Dry-run/diff/view use `utils/dry-run.ts` + `dry-run-formatter.ts`; `+ create`, `= skip (identical)`, `~/overwrite` markers; diff `-` local, `+` incoming (lab).
- Safety: `is-safe-target.ts` rejects NUL bytes, URL-encoded/double-encoded traversal, any `..` (except `[...slug]` routing patterns — so a file name containing `..` anywhere is rejected), Windows drive-letter paths outside cwd (win32: must start with cwd), absolute paths outside project root, `~` combined with `../`. It does NOT block in-project sensitive targets (`package.json`, `.github/workflows/*`, `AGENTS.md`, `.env*`, `~/…`) — registry items can write any in-project path → review before install. [V]
- `envVars` writer merges without overwriting; `.env*`-targeted registry:file merged into `.env.local` (lab).
